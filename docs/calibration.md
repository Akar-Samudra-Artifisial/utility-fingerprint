# Coordinate calibration: GRID game units → minimap pixels

> Generated by `uv run python -m utility_fingerprint_etl poc` (etl/src/utility_fingerprint_etl/poc_calibration.py).
> Aggregates only. Overlay images are written to `docs/poc/` (git-ignored: they plot derived data).

## Final formula

Using `https://valorant-api.com/v1/maps` (`xMultiplier`, `yMultiplier`, `xScalarToAdd`, `yScalarToAdd`, `displayIcon`), with GRID position `{x, y}` in cm and minimap of size `W×H` px:

```
u = y * xMultiplier + xScalarToAdd      # note: GRID y feeds the horizontal axis
v = x * yMultiplier + yScalarToAdd      # GRID x feeds the vertical axis (yMultiplier < 0)
col = u * W ; row = v * H               # origin top-left, row grows downward
```

- **Axes are swapped** (x↔y) relative to the naïve reading; no extra rotation or flip is needed on top of the formula when drawing `displayIcon` as-is (row 0 at the top). The negative `yMultiplier` already provides the vertical flip.
- GRID positions are in the same frame as valorant-api callout `location` (site centres land on plants; see below), so no offset between GRID and Riot coordinates is required.

## How correctness was checked

Top maps by games in `meta/games.csv` (title=val): `haven` (419), `lotus` (338). Up to 25 most recent finished games per map were sampled.

1. **Game-space check (independent of the image transform):** distance from each `player-completed-plantBomb` planter position (`actor.state.game.position`) to the nearest valorant-api site callout (`regionName == "Site"`). Plants must sit within a site (≤ 1500 cm).
2. **Pixel check:** after transforming, sample the minimap alpha channel at each point; plants and ability casts must land on drawn (opaque) map area, not on the transparent background. In addition, the minimap paints bomb sites with a yellow/olive tint (R,G > B+20) while corridors are neutral grey: plants should land on tinted pixels far more often than utility casts (baseline). The wrong (non-swapped) variant is evaluated for contrast.
3. **Visual check:** `docs/poc/<map>.png` — left panel final formula, right panel without swap. Plants (coloured by nearest site) must cluster on the A/B/C site areas of the drawn minimap; the white X marks are the callout centres transformed with the same formula.
4. **Bounds cross-check:** GRID `map.bounds` stretched onto the minimap's opaque bounding box (same orientation) vs the valorant-api formula.

## Conclusions

- Use the valorant-api formula with swapped axes (above) as the single source of truth; cache the coefficients and `displayIcon` per map at build time.
- GRID `map.bounds` agrees with the formula: stretched onto the minimap's opaque bounding box it lands within a few pixels of the valorant-api result (see per-map numbers). It is a usable fallback for maps missing from valorant-api and a sanity filter (drop positions outside it).
- valorant-api site callouts are label anchors, not geometric site centres (plant centroids sit tens of pixels away on some maps), so they are good for nearest-site classification but not as exact centres.
- Bomb sites are **not** in the GRID feed: derive the site from the plant position by nearest valorant-api site callout (all sampled plants are within 1500 cm of one, see distances above).
