### New data fields (additive; old data must stay valid)

- `teams/<id>.json` → `maps.<map>.utility.<side>.<phase>.<ability>.clusters[]`: each cluster gains
  `rounds` (distinct rounds with ≥ 1 cast in the cluster), `wins` (those rounds the team won) and
  `players: [[player_id, share], …]` (top 3 casters, share 0..1 of the cluster's casts).
- `teams/<id>.json` → `maps.<map>.phase_rounds.<side>.<phase> = { rounds, wins }`: baseline = rounds in
  which the team made ≥ 1 cast on that side and phase.
- `teams/<id>.json` root → `players: { "<player_id>": "<name>" }`.
- `display_icon_local: "/data/maps/<map>.png"` next to `display_icon` (may be absent). Today
  `display_icon` lives on `index.json` → `maps[]` (`MapMeta`); check the rebuilt files to see where the ETL
  put `display_icon_local` (expected: `index.json` `maps[]`).

## 1. Task 1 prompt (win rate in rounds when a cluster is used)

```text
Goal
On the Utility map tab, show for each utility cluster the team's round win rate in rounds when that
cluster was used, compared with a baseline (the team's win rate in all rounds where it used any utility
on the same side and phase). Be honest about sample size: few rounds → no rate; medium → rate with
interval and a low-sample badge; enough rounds → delta vs baseline, coloured only when the 95 % interval
excludes the baseline. The wording must not imply causation: always "win rate in rounds when used".

Data (already generated by the ETL; read web/public/data/teams/79.json to confirm the shape)
- cluster: `rounds` (number), `wins` (number), `players` ([player_id, share][]) — Task 2 uses `players`.
- map: `phase_rounds?: Partial<Record<Side, Partial<Record<Phase, { rounds: number; wins: number }>>>>`.
- Every new field is optional: data built before this change must still load and render (no win-rate UI
  then, no errors).

Relevant files (read them first)
- web/src/lib/data/types.ts
  - `Cluster` (~68-80), `TeamMapStats` (~97-107), `TeamFile` (~234-240), `MapMeta` (~30-38).
  - `Cluster` is shared with the Operator types (`OpSideStats.clusters` etc.); optional fields keep
    those valid.
- web/src/lib/data/select.ts
  - `ClusterView` (~22-33) has `phase` and `side`, so the baseline is
    `stats.phase_rounds?.[view.side]?.[view.phase]`.
  - `clusterViews()` (~114-139), `signatureClusters()` (~145-150), `SIGNATURE_MIN_COUNT` (~142).
- web/src/components/map/cluster-detail.tsx — popover of the highlighted cluster; `<dl>` rows at ~39-56,
  warning note at ~57-63.
- web/src/components/summary/summary-panel.tsx — "Signature utility" list (~105-150), `StatCard` /
  `Section` usage (~56-73).
- web/src/components/summary/map-insights.tsx — `mapInsights()` (~19-86) builds the Key insights cards
  (`Insight` type from ./key-insights.tsx); called from dashboard.tsx (~224-236).
- web/src/components/map/map-legend.tsx (~31-37) — uses `LegendHelp` from
  web/src/components/map/legend-help.tsx for the "How to read this map" text.
- web/src/components/ui/low-sample-badge.tsx (`LowSampleBadge`, takes `reason` incl. threshold),
  web/src/components/ui/stat-card.tsx (`StatCard`, `tone`: attack/defense/warning…),
  web/src/components/ui/section-header.tsx (`Section`/`SectionHeader`).
- web/src/app/globals.css — tokens `attack`, `defense`, `warning` (Tailwind `text-attack`,
  `text-defense`, `text-warning`, `border-l-…`); also used in print. Do not add hard-coded colours.
- web/src/lib/format.ts — `pct()`, `PHASE_LABEL`, `SIDE_LABEL`.
- web/AGENTS.md — this Next.js version differs from older ones; check `web/node_modules/next/dist/docs/`
  before using any Next.js API.

Scope
1. Types (types.ts): add optional `rounds?: number`, `wins?: number`,
   `players?: [playerId: string, share: number][]` to `Cluster`; a `RoundRecord { rounds: number;
   wins: number }` type; optional `phase_rounds` on `TeamMapStats`; optional root
   `players?: Record<string, string>` on `TeamFile`. JSDoc each field (meaning + denominator).
2. New pure module web/src/lib/stats.ts (no React):
   - `wilson(wins, n, z = 1.96): { rate: number; low: number; high: number } | null` — Wilson score
     interval; null when n = 0.
   - thresholds as named constants: `WIN_RATE_MIN_ROUNDS = 10`, `WIN_RATE_FULL_ROUNDS = 20`.
   - `clusterWinRate(cluster, baseline?)` returning a discriminated union:
     - `{ kind: "none" }` when `rounds`/`wins` are missing;
     - `{ kind: "count", rounds }` when rounds < 10 (show only "n rounds", no rate);
     - `{ kind: "low", rounds, rate, low, high }` when 10 ≤ rounds < 20 (rate + interval + low-sample badge);
     - `{ kind: "full", rounds, rate, low, high, baseline, deltaPp, significant }` when rounds ≥ 20;
       `baseline = baseline.wins / baseline.rounds` (if the baseline is missing or has 0 rounds, fall
       back to the "low" shape without delta), `deltaPp = (rate − baseline) × 100`,
       `significant = baseline < low || baseline > high`.
3. Cluster detail (cluster-detail.tsx): add a "Win rate in rounds when used" row/block:
   - none → nothing; count → "n rounds (too few for a rate)";
   - low → "54 % (95 % CI 31–75 %) · 13 rounds" + `LowSampleBadge` with reason
     "Only 13 rounds with this cluster (fewer than 20); interval is wide.";
   - full → rate + interval + "vs baseline 48 % → +6 pp". Colour the delta with `text-attack`
     (above baseline) / `text-defense` (below) ONLY when `significant`; otherwise muted text and a short
     "within noise" note. Never use red/green only: the sign (+/−) and words carry the meaning.
   ClusterDetail needs the baseline: pass it in as a prop (resolve it where ClusterDetail is rendered,
   e.g. map-canvas.tsx / dashboard.tsx) or extend `ClusterView` with `baseline?: RoundRecord` in
   `clusterViews()` — choose the smaller change and keep ids unchanged.
4. Summary panel (summary-panel.tsx): in each "Signature utility" row add a compact line, e.g.
   "Win 61 % in 23 rounds · +9 pp" (full), "Win 54 % · 13 rounds" + small badge (low), "8 rounds" (count).
   Keep rows on one line where possible (truncate). Add one sentence to the explanatory note under the
   list: "Win rate = rounds won when the cluster was used; baseline = all rounds with utility on this side
   and phase. Correlation, not cause."
5. Key insights (map-insights.tsx): add ONE card, label "Win rate when used", only if at least one cluster
   in the current filter has ≥ 20 rounds and `significant === true`; pick the one with the largest
   |deltaPp| (tie → more rounds). Title e.g. "Smoke A Main · 68 % vs 49 % baseline"; detail
   "+19 pp · 31 rounds · 95 % CI 51–82 %"; tone attack/defense by sign; clicking focuses the cluster like
   the "Signature setup" card. If no cluster qualifies, do NOT add a card (no empty placeholder).
   `mapInsights()` receives clusters via its input; pass the full filtered `derived.clusters` (not only
   signatures) from dashboard.tsx.
6. Legend help (map-legend.tsx → `LegendHelp` children): add 1–2 sentences: win rate in rounds when the
   cluster was used, Wilson 95 % interval, fewer than 10 rounds → no rate, 10–19 → low sample,
   coloured only when the interval excludes the baseline; not causal.

Constraints
- Copy wording: always "win rate in rounds when used" / "Win rate when used"; never "wins because of",
  "leads to", "causes".
- Pure functions in lib/stats.ts, no `any`, no `console.log`, TypeScript strict. No new npm dependencies.
  Use pnpm (no package-lock.json / yarn.lock).
- Reuse `StatCard`, `Section`/`SectionHeader`, `LowSampleBadge` and globals.css tokens; no ad-hoc colours.
- Old data (without the new fields) renders exactly as before.
- Print / PDF: Report tab "Export PDF" and print preview of the Utility map tab must not break.
- Do not touch `etl/`, `docs/data-pipeline.md`, anything under `web/public/data/`, or the Compare /
  Report / Operator tabs.
- Static export (`output: "export"`) must keep working. Do not commit; leave changes in the working tree.

Acceptance criteria (run from `web/`, dev server on any port)
- `pnpm lint` passes with no new errors; `pnpm build` passes.
- `/?team=79` (Cloud9, Utility map): clicking a signature cluster shows the win-rate block in the cluster
  detail with the rule that matches its `rounds` (check one cluster with < 10, one with 10–19, one with
  ≥ 20 rounds by trying other phases/sides, e.g. `/?team=79&phase=opening,mid`).
- A delta is coloured only when the interval excludes the baseline; spot-check one value by hand with
  the Wilson formula.
- The "Win rate when used" Key insights card appears only when a qualifying cluster exists; switching to a
  filter without one removes the card (no empty card).
- Summary panel rows show the compact win-rate line; the note explains baseline and "not cause".
- "How to read this map" contains the win-rate explanation, also in print preview (Cmd+P).
- With the new fields absent (e.g. temporarily point at an old JSON, or reason through the optional

- `git status` shows changes only under `web/src/`.

When done, list the files you changed and the commands you ran with their results.
```
